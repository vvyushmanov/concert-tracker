================================================================================
COUNTRY TABLE MIGRATION PLAN - AI-FRIENDLY PHASE-BASED APPROACH
================================================================================

PROJECT: lastfm-parser Concert Tracker
GOAL: Move country data from string field to dedicated Country table
REQUIREMENTS: 
  - Each country has: ID (int), full name (string), country code (string)
  - ZERO logic breakage
  - Support both MySQL and SQLite
  - Maintain backward compatibility during migration

================================================================================
MIGRATION STRATEGY
================================================================================

APPROACH: Gradual migration with backward compatibility

KEY DECISIONS:
1. Country table will have: id (PK), name (full name), code (2-letter code)
2. Concert.country → Concert.countryId (foreign key)
3. CityMapping.country → CityMapping.countryId (foreign key)
4. Keep country codes in COUNTRY_CODES setting (parser input)
5. Build country code → name mapping (hardcoded or from first scrape)

PHASES:
1. Schema Addition (backward compatible)
2. Data Migration (populate Country table)
3. Code Updates (dual-write period)
4. Schema Migration (add foreign keys, keep old columns)
5. Cleanup (remove old string columns)

PHASE 1: ADD COUNTRY TABLE (BACKWARD COMPATIBLE)
================================================================================

GOAL: Add Country table without breaking existing functionality

FILES TO MODIFY:
1. concert-tracker/prisma/schema.mysql.prisma
2. concert-tracker/prisma/schema.sqlite.prisma
3. concert-tracker/scripts/db_models.py

CHANGES:

A. Prisma Schemas (MySQL & SQLite)
   Add new model:
   ```prisma
   model Country {
     id       Int       @id @default(autoincrement())
     name     String    @unique @db.VarChar(100)  // "Turkey", "France"
     code     String    @unique @db.VarChar(10)   // "tr", "fr"
     createdAt Int
     updatedAt Int
     
     concerts     Concert[]
     cityMappings CityMapping[]
     
     @@index([code])
     @@index([name])
   }
   ```

B. SQLAlchemy Model (db_models.py)
   Add new class:
   ```python
   class Country(Base):
       __tablename__ = 'Country'
       
       id = Column(Integer, primary_key=True, autoincrement=True)
       name = Column(String, unique=True, nullable=False, index=True)
       code = Column(String, unique=True, nullable=False, index=True)
       createdAt = Column(Integer, nullable=False, default=lambda: int(datetime.utcnow().timestamp()))
       updatedAt = Column(Integer, nullable=False, default=lambda: int(datetime.utcnow().timestamp()))
       
       # Relationships
       concerts = relationship('Concert', back_populates='country_obj')
       city_mappings = relationship('CityMapping', back_populates='country_obj')
   ```
